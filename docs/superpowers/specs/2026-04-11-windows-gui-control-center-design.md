# Windows GUI Control Center Design

**Date:** 2026-04-11

**Status:** Approved in conversation, pending written spec review

## Goal

把现有项目调整为以 Windows 桌面 GUI 为主控入口，Web 端退化为报告中心。GUI 需要提供独立的资产发现、独立的漏洞匹配与服务识别、规则库导入、报告对比，以及一键启动 Web 报告中心的能力，同时避免“点击一次把整条扫描链路全跑完”的旧行为。

## Scope

本次设计覆盖：

- Windows 主控机下的 GUI 主流程
- Web 端职责收缩为报告查看与对比
- 资产发现与漏洞匹配模块的职责拆分
- Windows 优先的依赖与安装说明调整
- GUI 自适应布局与环境降级策略

本次设计不覆盖：

- 切换到新的桌面技术栈（如 PySide / PyQt）
- 重写底层扫描引擎
- 在 Web 端恢复扫描任务提交能力
- 新增分布式扫描、认证、远程代理执行

## Approved Decisions

### 1. 实现路线

采用“中等重构，保留现有后端能力”的方案：

- 保留现有扫描、报告、存储、规则管理、Web 报告中心能力
- 重整 GUI 页签结构、交互入口和平台适配
- 仅在必要处补充后端编排与数据标记

### 2. GUI 总体结构

GUI 采用 5 个页签：

1. 资产发现
2. 漏洞匹配与服务识别
3. 规则库导入
4. 报告对比
5. Web 报告中心

选择独立的 `Web 报告中心` 页签，而不是顶部全局控制栏。这样能释放顶部空间，避免主窗口过于紧凑，更适合 Windows 主控机的大屏展示与演示。

### 3. 模块边界

资产发现与漏洞匹配必须彻底分开：

- 资产发现页只负责目标网段发现和资产发现报告生成
- 漏洞匹配与服务识别页只负责基于用户输入网段独立运行 `nmap` 扫描、服务识别、漏洞匹配和分析报告生成
- 两个页签之间不能有自动串联
- 任一页签的“开始扫描”都只能触发本页自己的能力

### 4. 资产发现扫描方式

资产发现页默认展示：

- `递进式智能扫描（ICMP -> ARP -> SYN）`

同时提供“高级模式”展开区，允许自定义：

- 方法组合：`icmp` / `arp` / `syn`
- 端口范围
- 报告名称

递进式智能扫描延续当前发现引擎的分层补充逻辑：仅对前一步未发现的主机继续执行下一步，而不是对全网段重复做全量扫描。

### 5. 漏洞匹配与服务识别扫描方式

漏洞匹配页独立输入目标网段，不依赖资产发现快照。

GUI 提供 3 个 `nmap` 预设加 1 个高级入口：

- 快速扫描
- 标准扫描（默认）
- 深度扫描
- 高级自定义参数

目标是让普通演示流程使用预设即可完成，保留高级入口供论文实验或手工控制使用。

### 6. 规则库导入页

规则库导入页默认只显示：

- 本地规则文件选择
- 导入模式：`merge` / `replace`
- 当前规则库摘要

同页保留一个“高级功能”折叠区，用于远程 URL 更新：

- 不从系统中删除该能力
- 不作为默认主交互
- 不在 Web 端暴露该入口

### 7. 报告对比边界

报告对比默认对比第二页生成的分析报告。资产发现报告会进入报告中心供查看，但不作为默认的服务/漏洞差异对比对象。

这是为了避免把“仅资产可达性变化”和“服务/漏洞变化”混在同一对比模型里，保持对比语义清晰。

### 8. 环境与权限不足时的行为

Windows 主控版采用“尽量降级继续，但不伪造结果”的原则：

- 资产发现页：
  如果 `ARP` / `SYN` 因依赖、权限或平台限制不可用，则自动降级继续执行可用部分；GUI 状态区、日志区和最终报告必须写明降级原因。
- 漏洞匹配与服务识别页：
  如果 `nmap` 不可用，直接明确报错，不生成伪分析结果；若只是高级参数不适配，可以回退到标准扫描。
- 规则库远程更新：
  如果网络请求失败，明确返回失败原因，不修改现有规则库。

## Architecture

### GUI Layer

桌面端继续使用 `tkinter/ttk`，但调整为清晰的页签控制中心：

- 每个页签只负责一个主要用例
- 长任务继续通过现有异步执行框架运行，避免阻塞 UI
- 状态提示优先采用页内状态栏和日志区，而非大量模态弹窗

### Application Layer

保留现有 `ScanWorkbench`、`ScanOrchestrator`、`VulnerabilityRuleManager` 与 Web 控制逻辑，但需要重整工作台接口，明确两类独立报告：

- `asset_discovery_report`
- `analysis_report`

必要时在扫描记录中标记报告类型，供报告对比和历史列表过滤使用。

### Web Layer

Web 端定位为报告中心：

- 浏览历史报告
- 查看单次报告详情
- 执行报告对比

不再承担 GUI 主路径中的扫描任务提交。

## Page Design

### 1. 资产发现页

主要区域：

- 目标输入区
- 扫描方式区
- 高级模式折叠区
- 结果表格区
- 最近资产发现报告入口

主要动作：

- 开始资产发现
- 查看最新资产发现报告
- 刷新历史资产发现记录

产出：

- 独立资产发现报告
- 资产发现历史记录
- 如保留快照文件，则仅作为本页自己的历史留存与报告依据，不再驱动第二页

### 2. 漏洞匹配与服务识别页

主要区域：

- 目标输入区
- `nmap` 预设选择区
- 自定义参数折叠区
- 服务识别结果区
- 漏洞匹配结果区

主要动作：

- 开始分析
- 查看最新分析报告
- 刷新分析历史

产出：

- 独立分析报告
- 服务识别结果
- 漏洞匹配结果
- 可参与“报告对比”的分析历史记录

### 3. 规则库导入页

主要区域：

- 规则库摘要
- 本地文件导入区
- 高级功能折叠区（远程 URL 更新）

主要动作：

- 导入本地规则
- 展开高级功能后执行 URL 更新

### 4. 报告对比页

主要区域：

- 基线报告选择
- 新报告选择
- 对比摘要显示
- 打开 Web 对比页入口

主要动作：

- 执行本地摘要对比
- 一键打开 Web 对比页

### 5. Web 报告中心页

主要区域：

- 监听地址与端口配置
- 数据库路径显示
- 当前状态显示
- 启动 / 打开 / 停止按钮
- 运行日志

主要动作：

- 一键启动 Web
- 一键打开报告中心
- 停止 Web

## Layout and Responsiveness

为避免主窗口过于紧凑，GUI 采用“宽屏优先，窄屏自动堆叠”的布局策略：

- 默认窗口尺寸偏宽，适合 Windows 主控机
- 顶部只保留标题与必要状态，不承载复杂控制
- 页内参数区与结果区采用可伸缩双栏布局
- 窗口缩小时，双栏可退化为上下堆叠
- 表格、日志、摘要区域均提供滚动能力

目标是让常见 1080p 屏幕上能完整展示当前页的核心信息，而不是靠频繁切换或拥挤控件完成操作。

## Windows-First Dependency Strategy

依赖拆分为两层：

- `requirements.txt`：
  仅保留 Windows 主路径的必需 Python 依赖
- `requirements-advanced.txt` 或等价命名：
  放置 `scapy` 这类与 ARP/SYN、高权限或平台差异更强相关的可选依赖

安装文档改为 Windows 优先：

- Windows + Python + `nmap` + `tkinter` 为主路线
- Linux / WSL2 保留为补充说明
- `python3-tk`、`apt install`、`sudo`、`setcap`、`.sh` 双击脚本不再作为默认主说明

## Error Handling

错误处理分层如下：

- 参数错误：
  在当前页直接提示，不启动任务
- 环境缺失：
  明确显示“缺少什么、影响什么、如何修复”
- 可降级能力不可用：
  继续任务并记录降级说明
- 不可替代核心能力缺失：
  立即失败并阻止伪结果生成

任何情况下都不能把“环境问题导致未执行”伪装成“扫描结果为空”。

## Testing Strategy

本次改动属于明确行为变更，且涉及 GUI 工作流、报告类型、Windows 安装路径和模块边界，实施阶段需要使用测试保护。

优先测试方向：

- 资产发现与分析任务不会互相自动触发
- 资产发现生成的是独立资产报告
- 分析任务独立运行 `nmap` 路径
- Web 端保持报告中心职责，不恢复扫描提交
- 规则库本地导入与高级 URL 更新均可正常工作
- 缺少 `nmap`、缺少高级依赖时，GUI 行为符合降级/报错原则

## Risks

- 当前 GUI 文件职责较重，若继续堆叠逻辑，维护性会继续下降
- 现有发现逻辑含明显 Linux 权限假设，Windows 下需要谨慎设计降级提示
- 若不为扫描记录补充“报告类型”，历史列表与对比页容易混入资产发现报告
- `nmap` 在 Windows 下的可执行路径、返回格式与权限场景需要补充验证

## Acceptance Criteria

满足以下条件即可视为本次设计落地完成：

- GUI 提供 5 个页签，职责清晰
- Web 端只作为报告中心
- 资产发现与漏洞匹配互不自动串联
- 资产发现页默认使用递进式智能扫描
- 漏洞匹配页默认使用 `nmap` 标准扫描
- 规则库页默认简单，本地导入为主，远程 URL 更新保留在高级折叠区
- 报告对比默认仅对比分析报告
- Windows 主路径依赖与安装说明完成拆分和重写
- 环境不足时的降级或失败行为可见、可解释、不可伪装
