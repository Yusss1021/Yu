# 用户手册（第一次上手）

这份手册只回答一个问题：  
“我第一次打开这个软件，应该怎么理解它、怎么点、点完会发生什么？”

## 0. 启动前自检

如果还没装过依赖，直接双击 `install_deps.bat` 即可一键完成环境搭建。

否则，在双击 `start_gui.bat` 之前，请确认以下三项通过：

```powershell
# 1) Python 虚拟环境已创建且依赖已安装
.venv\Scripts\activate
python -c "import jinja2, flask; print('OK')"

# 2) nmap 已安装且可调用
nmap -V

# 3) GUI 可启动
python main.py gui
```

以上任何一步失败 → 先按 [INSTALL.md](./INSTALL.md) 完成环境配置。`start_gui.bat` 只启动不安装。

## 1. 先记住三句话

1. GUI 是主控入口
2. Web 端只负责看报告
3. 资产发现和漏洞匹配现在是两个独立模块

## 2. 你看到的五个页签分别是什么

### 2.1 资产发现

这一页只负责“找主机”。

你在这里做的事：

- 输入目标网段
- 选择扫描方式
- 点击开始

你得到的结果：

- 资产列表
- 资产发现历史
- 一份资产发现报告

不会发生的事：

- 不会自动开始漏洞匹配
- 不会因为上一页跑完就把第二页一起跑掉

### 2.2 漏洞匹配与服务识别

这一页只负责“识别服务 + 匹配漏洞 + 输出分析报告”。

你在这里做的事：

- 再次输入目标网段
- 选择 `nmap` 扫描预设
- 可选地打开主动探测或弱口令尝试
- 点击开始分析

你得到的结果：

- 服务识别表
- 漏洞匹配表
- 一份分析报告

### 2.3 规则库导入

这一页负责更新本地规则库。

默认能做：

- 从本地 JSON 文件导入
- 选择 `merge` 或 `replace`

高级功能里还能做：

- 从可信 URL 更新

### 2.4 报告对比

这一页负责比较两份分析报告。

它能回答：

- 新增了哪些服务
- 修复了哪些漏洞
- 哪些漏洞风险分发生了变化

### 2.5 Web 报告中心

这一页负责一键启动和打开 Web。

现在 Web 的定位很明确：

- 看报告
- 看扫描详情
- 做历史对比
- 删除报告

## 3. 你第一次操作时推荐怎么做

### 第一步：打开 GUI

最简单：

```text
双击 start_gui.bat
```

### 第二步：先做资产发现

在 `资产发现` 页：

1. 填目标网段
2. 不改设置，直接用默认递进式扫描
3. 点击开始

### 第三步：再做漏洞匹配

在 `漏洞匹配与服务识别` 页：

1. 再填一次目标网段
2. 保持 `标准扫描（推荐）`
3. 点击开始分析

### 第四步：查看 Web 报告中心

在 `Web 报告中心` 页：

1. 点击启动
2. 点击打开
3. 在浏览器中查看报告

## 4. 你最容易误会的地方

### 4.1 第一页跑完后，第二页为什么没自动开始

因为这正是新版设计目标。  
两个模块已经拆开了。

### 4.2 资产发现页为什么会提示降级

因为 Windows 下 `ARP/SYN` 会受权限、Npcap、虚拟网卡、代理环境影响。  
系统不会整页失败，而是：

- 记录原因
- 跳过不可用步骤
- 继续执行可用部分

### 4.3 第二页为什么会直接报 `nmap` 错误

因为第二页明确依赖 `nmap`。  
这不是 bug，而是防止给你“假分析结果”。

### 4.4 资产画像到底做什么

资产画像不是扫描方式，它只是在评分时告诉系统：

- 哪台资产更重要
- 哪台资产应该被更高权重对待

它不会改变：

- 主机数量
- 服务数量
- 端口本身是否开放

### 4.5 主动探测会不会影响结果

会。  
如果你开启了主动探测或弱口令尝试，命中的结果会进入最终风险评分。

## 5. 本机演示建议

如果你是为了毕设演示，推荐直接用项目自带靶场：

1. 双击 `lab\start_demo_lab.bat`
2. 在 GUI 中输入 `127.0.0.0/29`
3. 先跑资产发现
4. 再跑分析
5. 最后打开 Web 看报告

## 6. 最小自检

如果你怀疑环境坏了，先看下面三件事：

```powershell
nmap -V
python main.py gui
python -m unittest tests.test_desktop_gui_workflows tests.test_workbench_flow -v
```
