# 10 分钟答辩讲稿（GUI 主流程版）

这份讲稿按当前产品形态整理：

- GUI 是主控入口
- Web 端只负责报告中心
- 本地靶场优先用于现场演示

## 0. 演示前准备

推荐提前准备：

1. 双击 `lab\start_demo_lab.bat`
2. 双击 `start_gui.bat`
3. 保留至少两份分析报告，用于 `报告对比`

## 1. 开场（0:00 - 0:40）

“各位老师好，我的毕业设计题目是《面向企业内部网络的脆弱性扫描与风险评估系统设计与实现》。  
本系统的目标，是把企业内网中的资产发现、服务识别、漏洞匹配、配置弱点识别、风险量化、报告生成和历史对比整合成一个完整闭环，并以 Windows GUI 作为主控入口。”

## 2. 系统整体设计（0:40 - 1:40）

“系统当前分为五个页签：资产发现、漏洞匹配与服务识别、规则库导入、报告对比、Web 报告中心。  
其中 Web 端现在只保留报告中心职责，不再直接提交扫描任务。这样可以把扫描控制集中到桌面端，让使用流程更清晰，也更适合 Windows 主控机的实际演示环境。”

## 3. 资产发现演示（1:40 - 3:00）

操作：

1. 切到 `资产发现`
2. 输入 `127.0.0.0/29`
3. 默认扫描方式保持递进式
4. 点击 `开始资产发现`

口播重点：

- “这一页只负责发现主机和生成资产报告，不会自动触发漏洞匹配。”
- “这是本次重构的重要改进，解决了旧版本一次扫描所有功能一起跑的问题。”

## 4. 漏洞匹配与服务识别演示（3:00 - 5:00）

操作：

1. 切到 `漏洞匹配与服务识别`
2. 输入同样的目标网段
3. 保持 `标准扫描（推荐）`
4. 点击 `开始服务识别与漏洞匹配`

口播重点：

- “这一页独立调用 `nmap` 做服务识别。”
- “识别结果会先进入规则匹配，再叠加主动探测结果，最后统一进入风险量化模型。”
- “当前模型不仅考虑 CVSS，还考虑资产重要性、暴露面、可利用性和匹配置信度。”

## 5. 主动探测与弱口令说明（5:00 - 6:00）

操作：

1. 展开高级参数
2. 指向 `启用主动探测`
3. 指向 `启用少量空密码/弱口令尝试`

口播重点：

- “主动探测可识别 FTP 匿名访问、Redis 未授权、SNMP 默认 community 等配置类弱点。”
- “少量弱口令尝试支持 SSH、FTP、MySQL，默认关闭，需要手动开启。”
- “这些结果会进入最终报告分数，而不是旁路展示。”

## 6. 资产画像与风险抬升（6:00 - 6:50）

口播：

“系统支持资产画像。  
资产画像不会改变主机是否在线，也不会改变服务数量，但会改变资产重要性，从而影响最终风险分和优先级排序。  
这使得系统从‘只发现漏洞’进一步变成‘帮助判断先修什么’。”

## 7. 报告对比演示（6:50 - 7:50）

操作：

1. 切到 `报告对比`
2. 选择两份分析报告
3. 执行对比

口播：

“对比页可以展示服务新增、漏洞新增、已修复漏洞，以及持续风险分的变化。  
这比单次扫描更贴近真实运维场景，也体现了系统支持持续评估的能力。”

## 8. Web 报告中心演示（7:50 - 8:50）

操作：

1. 切到 `Web 报告中心`
2. 点击启动
3. 点击打开

口播：

“现在 Web 端只做报告中心，用来查看报告、扫描详情和历史对比。  
这种收口方式让 GUI 负责控制，Web 负责展示，职责更清晰，也更稳定。”

## 9. 删除报告与收尾（8:50 - 9:20）

操作：

1. 在 GUI 或 Web 中演示删除一份报告

口播：

“考虑到长期使用中报告会不断累积，我补充了报告删除功能。  
删除时会同时清理数据库记录和报告目录，避免历史数据越积越乱。”

## 10. 总结（9:20 - 10:00）

“总结来说，本系统已经实现了资产发现、服务识别、漏洞匹配、配置类弱点检测、风险量化、规则库管理、历史对比和报告中心管理等完整能力。  
相较于旧版本，本次工作的重点是模块解耦、Windows 主控机适配、GUI 可用性提升，以及将主动探测结果纳入统一风险模型。”

## 11. 高频追问口径

### 11.1 为什么要把资产发现和分析拆开？

“因为两者职责不同。资产发现关注的是主机发现，分析关注的是服务与风险评估。拆开后边界更清晰，也避免旧版本一次扫描把所有功能全跑完。”

### 11.2 主动探测结果会影响评分吗？

“会。主动探测命中的配置弱点会和规则匹配结果一起进入统一量化模型，因此会影响风险总数、风险等级分布和最终风险分。”

### 11.3 为什么 ARP 在你的 Windows 机器上会降级？

“因为当前主控机还受 Npcap、权限、代理和虚拟网卡环境影响，而且本地演示靶场本身是回环网段，不适合用 ARP 作为主验证方式。所以系统会自动降级继续，而不是整页失败。”

### 11.4 你的创新点是什么？

“我认为主要有四点：第一，形成了从发现到对比的完整闭环；第二，把资产画像与多因子风险量化结合起来；第三，把配置类弱点和少量主动探测引入统一评分；第四，完成了 Windows GUI 主控机下的集成交付。”
