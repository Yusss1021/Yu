# 安全与伦理说明（必读）

本项目定位是：

- 脆弱性扫描
- 配置弱点识别
- 风险评估与报告

它不是攻击工具，也不应该被用于未授权目标。

## 1. 使用前必须满足的条件

开始扫描前，你至少要同时满足这三项：

1. 明确授权
2. 明确范围
3. 明确时间窗口

推荐额外完成：

4. 通知相关运维 / 安全人员
5. 记录源 IP、目标网段、扫描方法与时间

## 2. 严格禁止的场景

以下行为不应执行：

- 扫描第三方公网主机
- 扫描不在你控制范围内的云服务器
- 扫描“公开练习环境”但没有明确授权边界
- 对生产环境进行高频、无通知、无维护窗口的主动探测

## 3. 扫描可能带来的影响

即使是评估型扫描，也可能造成：

- IDS / 防火墙告警
- 日志量增加
- 老旧设备短时抖动
- 对方误判为异常访问

因此推荐的执行顺序永远是：

1. 小范围试跑
2. 观察影响
3. 再扩大范围

## 4. Windows 主控机特别说明

在 Windows 上，`ARP/SYN` 与主动探测受这些因素影响：

- `scapy`
- `Npcap`
- 权限
- 虚拟网卡 / 代理环境
- 目标是否处于真实二层网络

所以系统被设计为：

- 条件满足就执行
- 条件不足就降级
- 不把整页 GUI 直接打死

## 5. 主动探测与弱口令尝试的边界

当前系统支持的主动探测与少量弱口令尝试，会对目标产生额外协议交互。

这意味着：

- 比纯 `nmap -sV` 更主动
- 更容易留下日志
- 更应该只用于授权环境

如果你要开启以下能力：

- `FTP anonymous`
- `Redis 未授权`
- `SNMP 默认 community`
- `SSH / FTP / MySQL` 弱口令尝试

请确认目标就是你自己控制的测试机或已获授权的实验环境。

## 6. 数据与报告保管

项目会保存：

- `data/scans.db`
- `reports/<name>/`
- `data/discovery_sessions/`

这些文件可能包含：

- IP / 网段
- 开放端口
- 服务与版本
- 风险结论

建议：

- 限制访问权限
- 对外展示时做脱敏
- 共享报告时共享整个报告目录，而不是单个 HTML

## 7. 外网验证的正确做法

如果你要验证“是否能探测外部网络”，正确路径是：

1. 使用你自己控制的公网 VPS / 云主机
2. 或使用书面授权给你的测试环境
3. 按 [external_validation_manual.md](./external_validation_manual.md) 执行

不建议直接扫描：

- 第三方公网资产
- 不明确授权的练习平台

## 8. 建议口径

如果你在答辩或论文里描述系统使用边界，建议使用这个表述：

“系统仅用于自有或明确授权的企业内网、实验网和公网测试主机的脆弱性评估，不对第三方未授权资产实施扫描、探测或弱认证尝试。”
