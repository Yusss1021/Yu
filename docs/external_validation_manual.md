# 外网验证手册（仅限自有或明确授权目标）

本文档用于验证项目是否具备“扫描外部网络”的能力。  
前提必须是：

- 目标由你自己控制，或你已获得明确授权
- 你已经阅读 [SECURITY_ETHICS.md](./SECURITY_ETHICS.md)

## 1. 不建议直接做的事

不要直接拿以下目标做测试：

- 第三方公网主机
- 不在你控制范围内的云资产
- 练习平台上未明确授权给你的环境
- 任何可能引发投诉、封禁或安全事件的公网地址

## 2. 推荐验证环境

建议最少准备 3 台你自己控制的目标：

### 2.1 基线主机

开放：

- `22`
- `80`
- `443`

用途：

- 验证连通性
- 验证 `nmap` 服务识别

### 2.2 弱配置主机

开放：

- `21`
- `6379`
- `3306`
- `161`

用途：

- 验证主动探测
- 验证弱口令尝试
- 验证 `LOW/MEDIUM/HIGH` 变化

### 2.3 对照主机

仅开放少量正常服务，不设置弱配置。

用途：

- 验证误报控制
- 验证主动探测关闭后的对照结果

## 3. 验证前清单

开始前逐项确认：

1. `nmap -V` 正常
2. GUI 可启动
3. 数据库路径固定
4. 目标 IP、端口、授权材料已记录
5. 扫描时间窗口已确认
6. 需要的话提前通知运维或安全人员

## 4. 验证场景

### 场景 A：基础连通性与资产发现

目标：

- 确认 GUI 能发现公网主机

步骤：

1. 在 `资产发现` 页输入一个你控制的小网段或单公网 IP
2. 先用 `icmp`
3. 再用 `icmp,syn`

记录：

- 是否发现主机
- 是否出现降级提示
- 不同方法组合下的差异

### 场景 B：服务识别

目标：

- 确认 `nmap` 能识别公网服务

步骤：

1. 在分析页输入目标
2. 预设选 `标准扫描（推荐）`
3. 候选端口填已知开放端口

记录：

- 服务名
- 产品名
- 版本号
- 指纹置信度

### 场景 C：主动探测

目标：

- 验证配置类弱点是否被识别

建议目标：

- 开放 `FTP anonymous`
- 开放未授权 `Redis`
- 开放 `SNMP public/private`
- 开放 `Telnet`

步骤：

1. 在分析页开启 `启用主动探测`
2. 运行一轮分析

预期：

- 报告中出现 `CFG-*` 规则 ID
- 风险总数高于关闭主动探测时

### 场景 D：弱口令尝试

目标：

- 验证 `SSH / FTP / MySQL` 的少量弱口令探测

步骤：

1. 在目标主机上布置一个已知弱配置
2. 在分析页开启 `启用少量空密码/弱口令尝试`
3. 运行一轮分析

预期：

- 命中 `CFG-SSH-WEAK-PASSWORD-0001`
- 或 `CFG-FTP-WEAK-PASSWORD-0002`
- 或 `CFG-MYSQL-WEAK-PASSWORD-0001`

### 场景 E：资产画像

目标：

- 验证相同目标在不同画像下的评分变化

步骤：

1. 不使用资产画像做一次分析
2. 使用高重要性画像做第二次分析
3. 进入报告对比

预期：

- 服务数保持不变
- 风险分提高
- 某些风险等级可能被抬升

### 场景 F：报告中心

目标：

- 验证 Web 报告中心对外网扫描结果的可视化是否正常

步骤：

1. 在 GUI 中启动 Web 报告中心
2. 打开首页
3. 查看扫描详情
4. 打开独立报告
5. 试删一份不再需要的报告

## 5. 建议记录模板

每个目标建议至少记录：

- 目标 IP / 网段
- 开放端口
- 使用的分析预设
- 是否开启主动探测
- 是否开启弱口令尝试
- 是否使用资产画像
- 服务识别结果
- 漏洞 / 规则命中结果
- 风险总数与等级分布
- 误报 / 漏报观察

## 6. 推荐形成的验证结论

外网验证结束后，你最好能回答这些问题：

1. 项目能否识别公网目标的基础服务
2. 主动探测能否对你控制的弱配置做出有效提示
3. 弱口令探测是否能命中已知测试账号
4. 资产画像是否只影响评分，不影响服务识别数量
5. 报告与对比页面是否能直观看出变化

## 7. 推荐口径

如果你要把外网验证写进论文或答辩，建议统一使用这个表述：

“外部网络验证仅在自有或明确授权的公网测试主机上进行，用于验证本系统在真实网络链路下的连通性、服务识别、配置类弱点识别和风险量化能力，不对第三方公网资产实施未授权扫描。”
